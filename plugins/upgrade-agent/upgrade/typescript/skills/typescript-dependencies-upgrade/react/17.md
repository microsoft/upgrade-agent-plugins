# React 17 — breaking changes

React 17 was the "transitional" release — almost no new developer-facing features. Its main role today is as a stepping-stone for codebases coming from React 16 toward 18 or 19. If you're already on 17 and going to 18/19, this file has nothing to add — go straight to `react/18.md` and `react/19.md`.

## Event delegation moved from `document` to the root container

This is the only behavior change you're likely to hit. In React ≤ 16, React attached event listeners to `document`. In 17, React attaches them to the root container element (the one passed to `ReactDOM.render` or `createRoot`).

Impact: code that calls `document.addEventListener` for events that React handles will now run **before** React's handler, not at the same level. This usually doesn't matter, but it breaks two specific patterns:

- **`stopPropagation` from a vanilla `document` listener will no longer prevent React handlers** (they're below `document` now).
- **`document.addEventListener('click', handler)` for "outside click" patterns** continues to work but now fires in addition to React click handlers in a different order. Verify modal-close / dropdown-close logic still behaves correctly.

No automated migration — search for `document.addEventListener` and review each call.

## New JSX transform (optional but recommended)

React 17 introduced the new JSX transform so you no longer need `import React from 'react'` in every file. This is **optional** in 17 but becomes the default in 18 and the only supported transform in 19's removal sweep. Enabling it now reduces noise in later upgrades:

- TypeScript: set `"jsx": "react-jsx"` (or `"react-jsxdev"` in dev) in `tsconfig.json`.
- Babel: update `@babel/preset-react` to `{ runtime: 'automatic' }`.

After switching the transform, you can remove unused `import React from 'react'` lines (ESLint's `react/jsx-uses-react` and `react/react-in-jsx-scope` rules can be turned off, and `no-unused-vars` will flag the leftover imports).

## Ecosystem peer-dep churn

React 17's ecosystem was largely contemporaneous with 16's, so peer-dep adjustments are usually minor:

- **`@types/react` / `@types/react-dom`** must be in the 17.x line if you're stopping at 17. If your final target is 18 or 19, skip the 17.x types entirely and jump to the target major's types in one step.
- **`@testing-library/react`** v11+ supports React 17.
- **`react-router`** v5 supports React 17; v6 supports both 17 and 18.

If your target is 18 or 19, treat React 17 as a transit point — don't waste time perfecting the 17 state. Bump straight to the target major and apply the per-major guidance for 18/19.
