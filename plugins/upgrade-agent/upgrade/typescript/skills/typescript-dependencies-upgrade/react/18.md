# React 18 — breaking changes

React 18 introduced concurrent rendering and the new root API. If your target is 19 (most common), the React 19 file applies too. This stays a **single-shot** upgrade — you bump straight to the target, not to 18 first — but apply 18's migration items as well as 19's, handling 18's first because several are prerequisites for 19's hard removals.

## New root API (preferred starting in 18, mandatory in 19)

In 18 these legacy APIs — `ReactDOM.render` / `ReactDOM.hydrate` / `unmountComponentAtNode` — were deprecated (they print a console warning at runtime); 19 removes them entirely. Migrate every call site as part of this upgrade:

- **`ReactDOM.render(element, container)` → `createRoot(container).render(element)`.** `createRoot` is imported from `react-dom/client` (NOT `react-dom`).
- **`ReactDOM.hydrate(element, container)` → `hydrateRoot(container, element)`.**
- **`unmountComponentAtNode(container)` → `root.unmount()`.** Save the value returned by `createRoot` so you can call `unmount()` on it later.
- **The third `callback` argument to `render`/`hydrate` was removed.** Move any post-render logic into a `useEffect` in a top-level component.

If your target is 19, these calls won't work at all and must be migrated — see [react/19.md](./19.md).

## Strict-mode double-invocation (dev only)

React 18 Strict Mode intentionally double-invokes the following in development to surface non-idempotent code (the runtime behavior is unchanged in production):

- Function-component bodies
- `useState` / `useReducer` initializer functions
- `useEffect` / `useLayoutEffect` setup AND cleanup functions (effects run → cleanup runs → effects run again)
- Class component `constructor`, `render`, and `shouldComponentUpdate`

Components must be resilient: any effect that subscribes/registers/allocates must release the resource in cleanup. Patterns that break under double-invocation:

- Effects that call `fetch` without cleanup → fires two requests; cancel with `AbortController` in cleanup.
- Effects that initialize a singleton (chart instance, map, websocket) → second mount creates a duplicate; track and destroy in cleanup.
- `useRef`-based "did mount" guards (`if (!hasMounted.current) { hasMounted.current = true; doSideEffect(); }`) → fires only once but the effect cleanup still runs twice; usually a sign the code should be restructured.

## Automatic batching

React 18 batches state updates across promises, timeouts, native event handlers, etc. — in 17, only updates inside React event handlers were batched. The default change is almost always desirable, but if you have a code path that relies on a re-render between two `setState` calls in the same microtask, wrap one in `flushSync` from `react-dom`:

```ts
import { flushSync } from 'react-dom';
flushSync(() => setA(1));
setB(2); // Now in a separate render.
```

## Server rendering (SSR)

If the app uses `react-dom/server`: `renderToNodeStream` is deprecated — switch to `renderToPipeableStream` (Node) or `renderToReadableStream` (edge runtimes). `renderToString` / `renderToStaticMarkup` still work but have limited Suspense support.

## TypeScript-specific changes

- **`children` is no longer implicit on `React.FC`.** If you used `FC<{}>` with children, add `PropsWithChildren` or declare `children?: ReactNode` explicitly. Many codebases see this as a wide-impact compile error after the bump — the auto-fixer in `types-react-codemod` handles most cases.
- **Stricter event types.** Some event-handler prop types tightened (e.g., `onChange` for inputs). Compile errors are easy to fix locally; usually means switching from a generic `Event` to a specific `ChangeEvent<HTMLInputElement>`.
- **`useState`/`useReducer` setter inference improved**, occasionally surfacing previously-hidden type errors.

## New APIs worth knowing

These are not required but you may want to adopt them as part of the upgrade:

- `startTransition` / `useTransition` — mark non-urgent state updates so React can interrupt them for higher-priority renders.
- `useDeferredValue` — defer expensive re-renders for derived state.
- `useId` — generate stable IDs for `aria-*` / form-label use cases that work with SSR hydration.
- `useSyncExternalStore` — official hook for subscribing to external stores. Most state libraries already wrap this internally.

## Ecosystem peer-dep churn

- **`@types/react` / `@types/react-dom`** must be in the 18.x line.
- **`@testing-library/react`** requires v13+ for React 18.
- **`react-router` / `react-router-dom`** v6+ supports React 18 natively.
- **`react-redux`** requires v8+ for React 18.
