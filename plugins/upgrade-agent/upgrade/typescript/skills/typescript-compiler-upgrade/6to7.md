# TypeScript 7.0 Migration (from 6.x)

TypeScript 7.0 is published as the `typescript` package on npm, the same as previous major versions, and the compiler binary is still `tsc`. It is a native (Go) port that is behavior-compatible with 6.0's type checker.

## Install

**npm:** `npm install -D typescript@7`
**yarn:** `yarn add -D typescript@7`
**pnpm:** `pnpm add -D typescript@7`

Nightly builds now ship under `typescript@next`. The old `@typescript/native-preview` package is no longer the recommended install path.

## Upgrade Checklist

1. Before installing TypeScript 7, inspect declared dependencies and their peer-dependency ranges for packages whose supported TypeScript range excludes 7.
2. If any declared dependency requires TypeScript lower than 7, name the incompatible packages and ask the user whether they want to upgrade those dependencies as part of this migration. Do not silently retain or add an older TypeScript version to accommodate them.
3. If the user agrees, invoke the `typescript-dependencies-upgrade` skill for the confirmed packages and try to upgrade them to versions that support TypeScript 7. Then resume this compiler-upgrade flow. If no compatible version exists or the dependency upgrade fails, report the blocker and ask before replacing or removing the dependency.
4. If the user declines, leave those dependencies unchanged and, before continuing, explain that they may block a complete TypeScript 7 migration. Offer the side-by-side setup below — install TypeScript 7 as the aliased `@typescript/native` package while `typescript` resolves to the 6.0 API — so tooling that needs the older API keeps working.
5. Install `typescript@7` (or `typescript@latest` if 7.x is current).
6. Run `typescript_compile_package` to check for errors.
7. Fix any deprecated feature errors — all TS6 deprecations that were still opt-out in 6.0 are hard errors in 7.0. `ignoreDeprecations` is no longer supported.

No `package.json` script rewrites are required for this hop: `tsc` remains the compiler entry point, and 7.0 does not change any config defaults beyond what 6.0 already introduced (see [5to6.md](./5to6.md)).

## Forbidden Fixes — Do Not Suppress Errors

Do not paper over upgrade errors with suppression escape hatches. Specifically:

- **`ignoreDeprecations`** has no effect in TS7 — the deprecated options are fully removed. Never add it as a fix on this hop. Fix the underlying issue using the recipes in [5to6.md](./5to6.md).
- Do not add `// @ts-ignore`, `// @ts-expect-error`, or `// @ts-nocheck` to silence new errors.
- Do not cast to `any` (or widen types to `any`) just to make an error go away.
- Do not flip `tsconfig.json` strictness flags (`strict`, `noImplicitAny`, `strictNullChecks`, `skipLibCheck`, etc.) from their existing value to silence errors.

If an existing `ignoreDeprecations` entry is already in `tsconfig.json`, leave it as-is. If a real fix is genuinely out of scope, revert the upgrade for that package rather than committing a suppression.

## Running TS6 and TS7 Side-by-Side (tools that need the TypeScript API)

TypeScript 7.0 does not ship a programmatic API — 7.1 will ship a new, different API. Until then, some tools still need the 6.x API surface (e.g. `typescript-eslint`, bundlers/formatters that generate `.d.ts` files, Angular's compiler, and other framework toolchains). For those projects, install the `@typescript/typescript6` compatibility package alongside `typescript@7`.

`@typescript/typescript6` re-exports the TypeScript 6.0 API and ships a `tsc6` executable so it doesn't collide with 7.0's `tsc`.

**Recommended layout** (7.0 is the default `tsc`, and imports of `typescript` resolve to the 6.0 API for tools that need it):
```json
{
  "devDependencies": {
    "@typescript/native": "npm:typescript@^7.0.2",
    "typescript": "npm:@typescript/typescript6@^6.0.2"
  }
}
```
With this in place, `npx tsc` runs the 7.0 compiler, `npx tsc6` runs the 6.0 compiler, and any tool that does `import ts from "typescript"` gets the 6.0 API.

**Alias-only variant** (if the project doesn't need the 7.0 `tsc` binary, only the 6.0 API for tooling):
```
npm install -D typescript@npm:@typescript/typescript6
```
or
```json
{
  "devDependencies": {
    "typescript": "npm:@typescript/typescript6@^6.0.2"
  }
}
```

Only reach for this side-by-side setup after following the dependency-upgrade decision flow above: the user declined the dependency upgrade, or no compatible dependency version exists, and the project still needs the older TypeScript API. Do not use side-by-side TypeScript versions as a substitute for asking whether an incompatible dependency should be upgraded. Plain application projects should just install `typescript@7` and use `tsc` as normal.
